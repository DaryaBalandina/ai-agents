# Specification: Tracker

## 1. Управление задачами

### Requirement: Отображение задач

Система MUST отображать список учебных задач.

Каждая задача MUST содержать:
- id — уникальный идентификатор;
- title — название задачи;
- hours — количество часов;
- done — статус выполнения (true/false).

### Requirement: Стартовые задачи

Система MUST при первом запуске отображать три задачи:

| title | hours | done |
|---|---:|---|
| Чтение | 2 | true |
| Практика | 4 | false |
| Повторение | 2 | false |

### Scenario: Первый запуск

WHEN пользователь открывает приложение впервые
THEN система отображает три стартовые задачи
AND показывает 8 общих часов
AND показывает 2 выполненных часа
AND отображает прогресс 25%.

### Requirement: Добавление задачи

Система MUST позволять пользователю добавлять задачи.

Новая задача MUST получать уникальный id.
Новая задача MUST иметь done=false.

### Scenario: Успешное добавление

WHEN пользователь вводит корректное название и количество часов
AND отправляет форму
THEN новая задача появляется в списке
AND сохраняется в общем наборе данных
AND форма очищается.

### Requirement: Удаление задачи

Система MUST позволять удалять существующие задачи.

### Scenario: Удаление

WHEN пользователь нажимает кнопку удаления задачи
THEN задача удаляется из набора данных
AND исчезает из отображаемого списка
AND показатели пересчитываются.

### Requirement: Переключение статуса

Система MUST позволять переключать значение done между true и false.

### Scenario: Отметка задачи выполненной

WHEN пользователь отмечает активную задачу как выполненную
THEN значение done меняется на true
AND показатели выполненных часов и прогресса пересчитываются.

### Scenario: Возврат задачи в активные

WHEN пользователь снимает отметку выполнения
THEN значение done меняется на false
AND показатели пересчитываются.

## 2. Валидация формы

### Requirement: Валидация названия

Система MUST проверять название задачи после применения trim.

Название MUST содержать хотя бы один непробельный символ.

### Scenario: Пустое название

WHEN пользователь отправляет форму с пустым названием
OR вводит только пробелы
THEN система показывает ошибку рядом с полем названия
AND не добавляет задачу
AND сохраняет введенные данные формы.

### Requirement: Валидация часов

Система MUST принимать количество часов:
- от 0,5 до 24 включительно;
- с шагом 0,5.

Пустое значение MUST считаться ошибкой,
а не нулевым значением.

### Scenario: Некорректное количество часов

WHEN пользователь вводит пустое значение
OR значение меньше 0,5
OR значение больше 24
OR значение не соответствует шагу 0,5
THEN система показывает ошибку рядом с полем часов
AND не добавляет задачу
AND сохраняет введенные данные формы.

### Scenario: Корректное количество часов

WHEN пользователь вводит число от 0,5 до 24
с шагом 0,5 включительно
THEN значение принимается системой.

### Requirement: Отображение ошибок

Система MUST отображать сообщения об ошибках рядом
с соответствующими полями формы.

Ошибки MUST быть понятными пользователю.

## 3. Фильтрация

### Requirement: Фильтр задач

Система MUST предоставлять три режима фильтрации:
- Все;
- Активные;
- Готовые.

Фильтр MUST влиять только на видимый список задач.

Общие часы, выполненные часы и прогресс MUST рассчитываться
по всем задачам независимо от выбранного фильтра.

### Scenario: Фильтр активных задач

WHEN пользователь выбирает фильтр «Активные»
THEN система отображает только задачи с done=false
AND сохраняет общие показатели по всем задачам.

### Scenario: Фильтр готовых задач

WHEN пользователь выбирает фильтр «Готовые»
THEN система отображает только задачи с done=true
AND сохраняет общие показатели по всем задачам.

### Scenario: Отображение всех задач

WHEN пользователь выбирает фильтр «Все»
THEN система отображает все существующие задачи.

## 4. Расчет показателей

### Requirement: Общие часы

Система MUST рассчитывать сумму часов всех задач.

### Requirement: Выполненные часы

Система MUST рассчитывать сумму часов задач, у которых done=true.

### Requirement: Процент выполнения

Система MUST рассчитывать прогресс по формуле:

progress = round(100 * completedHours / totalHours)

Если задач нет или сумма часов равна нулю,
прогресс MUST составлять 0%.

Система MUST исключать появление NaN и Infinity.

### Scenario: Начальные показатели

WHEN приложение загружено со стартовыми задачами
THEN общая сумма составляет 8 часов
AND выполненная сумма составляет 2 часа
AND прогресс составляет 25%.

### Scenario: Изменение статуса задачи

WHEN пользователь отмечает задачу «Практика» выполненной
THEN выполненная сумма составляет 6 часов
AND общая сумма остается 8 часов
AND прогресс составляет 75%.

### Scenario: Пустой список

WHEN все задачи удалены
THEN общая сумма составляет 0 часов
AND выполненная сумма составляет 0 часов
AND прогресс составляет 0%.

## 5. Интерфейс

### Requirement: Адаптивность

Интерфейс MUST корректно отображаться на ширине экрана 390 px.

Система MUST исключать горизонтальную прокрутку.

### Requirement: Подписи элементов

Все поля ввода и кнопки MUST иметь понятные подписи.

Пользователь MUST понимать назначение каждого элемента управления.

## 6. Автономность

### Requirement: Независимость от внешних ресурсов

Приложение MUST работать без:
- CDN;
- внешних JavaScript-библиотек;
- API-ключей;
- серверной части.

Вся необходимая HTML-, CSS- и JavaScript-логика MUST
находиться внутри одного файла tracker-v2.html.

### Requirement: Локальное сохранение (необязательно)

Система MAY сохранять задачи в localStorage.

WHEN localStorage недоступен
THEN система MUST продолжать работу с данными в памяти
AND показывать понятное сообщение пользователю.
