# Design: Mini Task Tracker

## 1. Архитектура

Приложение реализуется как одностраничное автономное веб-приложение.

Файл:
tracker-v2.html

Структура файла:
- HTML — разметка интерфейса;
- CSS — стили и адаптивность;
- JavaScript — данные, логика, обработчики событий и расчеты.

Внешние библиотеки и сетевые зависимости отсутствуют.

## 2. Модель данных

Каждая задача представлена объектом:

{
  id: number | string,
  title: string,
  hours: number,
  done: boolean
}

Поля:

| Поле | Тип | Описание |
|---|---|---|
| id | number/string | Уникальный идентификатор |
| title | string | Название задачи |
| hours | number | Количество часов |
| done | boolean | Статус выполнения |

## 3. Начальное состояние

Массив задач при первом запуске:

[
  {
    id: 1,
    title: "Чтение",
    hours: 2,
    done: true
  },
  {
    id: 2,
    title: "Практика",
    hours: 4,
    done: false
  },
  {
    id: 3,
    title: "Повторение",
    hours: 2,
    done: false
  }
]

## 4. Логика операций

### Добавление

1. Получить значения полей формы.
2. Применить trim к названию.
3. Проверить название и часы.
4. Если есть ошибки — отобразить их рядом с полями.
5. Сохранить введенные значения формы.
6. Если ошибок нет — создать новую задачу.
7. Добавить задачу в общий массив.
8. Обновить список и показатели.

### Удаление

1. Получить id выбранной задачи.
2. Удалить соответствующую задачу из массива.
3. Обновить список.
4. Пересчитать показатели.

### Переключение статуса

1. Получить id задачи.
2. Изменить значение done на противоположное.
3. Обновить список.
4. Пересчитать показатели.

### Фильтрация

Фильтр хранится отдельно от массива задач.

Возможные значения:
- all;
- active;
- done.

Фильтрация применяется только при формировании
отображаемого списка.

Исходный массив задач не изменяется.

## 5. Расчеты

Обозначения:

- totalHours — сумма часов всех задач;
- completedHours — сумма часов выполненных задач;
- progress — процент выполнения.

Формулы:

totalHours = сумма hours всех задач.

completedHours = сумма hours задач,
для которых done === true.

progress = round(100 * completedHours / totalHours).

Защита от деления на ноль:

Если totalHours === 0,
progress = 0.

Пример начальных расчетов:

totalHours = 2 + 4 + 2 = 8

completedHours = 2

progress = round(100 * 2 / 8) = 25%

После выполнения задачи «Практика»:

totalHours = 8

completedHours = 2 + 4 = 6

progress = round(100 * 6 / 8) = 75%

## 6. Валидация

### Название

- Применяется trim.
- После trim строка не должна быть пустой.

### Часы

- Значение обязательно.
- Минимум: 0,5.
- Максимум: 24.
- Шаг: 0,5.

Проверка шага может выполняться через условие:
hours * 2 является целым числом.

Пустая строка проверяется отдельно до преобразования
в числовой тип.

При ошибке:
- задача не создается;
- сообщение показывается рядом с полем;
- значения формы сохраняются.

## 7. Состояние интерфейса

Необходимые элементы:

1. Заголовок приложения.
2. Блок общих показателей:
   - всего часов;
   - выполнено часов;
   - процент выполнения.
3. Индикатор прогресса.
4. Форма добавления задачи:
   - поле названия;
   - поле часов;
   - кнопка добавления.
5. Фильтры:
   - Все;
   - Активные;
   - Готовые.
6. Список задач:
   - название;
   - количество часов;
   - переключатель статуса;
   - кнопка удаления.

## 8. Адаптивность

Основная контрольная ширина: 390 px.

Интерфейс должен:
- помещаться в ширину экрана;
- не создавать горизонтальную прокрутку;
- сохранять читаемость текста;
- обеспечивать доступность подписей полей и кнопок.

## 9. Необязательное хранение данных

При реализации localStorage:
- задачи сохраняются после изменений;
- при следующем запуске загружаются сохраненные задачи;
- если сохраненных данных нет, используются стартовые задачи;
- при ошибке доступа к хранилищу приложение продолжает
  работу с массивом в памяти;
- пользователю отображается понятное сообщение
  о недоступности сохранения.
